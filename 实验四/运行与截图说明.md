## 图01 前台编辑器挂起与后台查找

逐条操作：

```bash
vi f4
```

进入 vi 后直接按 **Control + Z**（不是 Command + Z），回到 Shell 提示符。vi 是终端编辑器，可以完成本题，不需要桌面环境。

再执行：

```bash
bash -c 'sleep 30; find / -name inittab 2>f5.err' > f5 &
jobs -l
```

此时立刻截图，文件名 `图01_前后台作业.png`。应看到 vi 为 Stopped，查找作业为 Running。延迟 30 秒是为了保留前后台切换的操作时间；查找结果仍保存到 f5，权限错误单独保存到 f5.err。

截图后尽快进入下一步。若查找已经完成，可重新执行上面的后台命令，再继续。

## 图02 作业切换与进程用户信息

先单独执行：

```bash
fg %2
```

先用 `jobs -l` 核对编号。用户图01的查找作业是 `[2]`，所以使用 `%2`；如果重新启动后变成其他编号，改用实际编号。不能用 `%+` 代替：停止的 vi 可能是当前作业，用户图01中 `[1]+` 正是 vi。等待提示符重新出现，再逐条运行：

```bash
cat f5
wc -l f5
head -n 3 f5.err
jobs -l
```

查看 vi 对应的作业号，再终止它。如果 `jobs -l` 显示 vi 是 `[1]`，执行：

```bash
kill -9 %1
```

如果是其他编号，把 `%1` 换为实际编号。然后运行：

```bash
jobs
ps -l
who -H
```

保存 `图02_作业切换与进程用户.png`；一屏放不下可分两张。f5 为空可能是本系统不存在 inittab；f5.err 出现 Permission denied 是普通账户查找受限目录的实际结果。`who -H` 只有表头也按实际截图。

## 图06 每天及每三个月的 cron 配置

这一部分使用 testuser，不创建 helen 账户。先在 root 终端执行以下命令，把本次实验目录的所有者交给 testuser，然后切换账户（不递归修改已有文件）：

```bash
chown testuser:testuser /home/testuser/os_lab4_24122233
su - testuser
```

再备份当前 crontab，下面这段完整复制一次：

```bash
cd /home/testuser/os_lab4_24122233
backup_dir=$(mktemp -d "$PWD/cron_backup.XXXXXX")
if crontab -l > "$backup_dir/original.cron" 2> "$backup_dir/read.err"; then
    touch "$backup_dir/had_crontab"
elif LC_ALL=C crontab -l 2>&1 | grep -q '^no crontab for '; then
    : > "$backup_dir/original.cron"
else
    cat "$backup_dir/read.err"
    echo 'STOP: cannot read current crontab'
fi
```

如果显示 STOP，停止 cron 配置并反馈错误。正常情况下继续：

```bash
cat > lab4.cron <<'EOF'
# BEGIN OS_LAB4_24122233
30 8 * * * /usr/bin/ps > /home/testuser/os_lab4_24122233/ps.log
0 0 1 */3 * /usr/bin/who > /home/testuser/os_lab4_24122233/who.log
# END OS_LAB4_24122233
EOF
cat "$backup_dir/original.cron" lab4.cron > "$backup_dir/installed.cron"
crontab "$backup_dir/installed.cron"
crontab -l
```

保存 `图06_cron定时配置.png`。两行分别表示每天 08:30，以及 1、4、7、10 月的 1 日 00:00。参考材料的 `0 0 * */3 *` 会在这些月份的每天执行，不符合“1号”的要求，因此本次改为 `0 0 1 */3 *`。

## 图07 临时按分钟验证 cron

不修改服务器系统时间。添加两条每分钟验证任务，同时保留图06的正式配置：

```bash
cat > lab4_test.cron <<'EOF'
# BEGIN OS_LAB4_TEST_24122233
* * * * * /usr/bin/date >> /home/testuser/os_lab4_24122233/cron_test.log; /usr/bin/ps > /home/testuser/os_lab4_24122233/ps_test.log; /usr/bin/who > /home/testuser/os_lab4_24122233/who_test.log; /usr/bin/who | /usr/bin/wc -l > /home/testuser/os_lab4_24122233/who_test.count
# END OS_LAB4_TEST_24122233
EOF
crontab -l > "$backup_dir/before_test.cron"
cat "$backup_dir/before_test.cron" lab4_test.cron > "$backup_dir/with_test.cron"
crontab "$backup_dir/with_test.cron"
crontab -l
date
```

等下一次分钟切换，再多等几秒。可以先做后面的系统监视。然后执行：

```bash
cat cron_test.log
cat ps_test.log
cat who_test.log
cat who_test.count
ls -l ps_test.log who_test.log
```

保存 `图07_cron自动执行.png`。若暂时提示文件不存在，等下一分钟再查看。若 who 没有登录记录，who_test.log 为零字节、who_test.count 为 0 都是有效结果。这里验证的是临时每分钟任务；每天及每三个月的配置并没有在截图时自动到期。

## 图08 删除本次 cron 调度

应在完成图07后清理。只移除本次两个带标记的区块，保留用户其他调度：

```bash
crontab -l > "$backup_dir/before_cleanup.cron"
sed '/^# BEGIN OS_LAB4_24122233$/,/^# END OS_LAB4_24122233$/d; /^# BEGIN OS_LAB4_TEST_24122233$/,/^# END OS_LAB4_TEST_24122233$/d' "$backup_dir/before_cleanup.cron" > "$backup_dir/remaining.cron"
if grep -q '[^[:space:]]' "$backup_dir/remaining.cron"; then
    crontab "$backup_dir/remaining.cron"
else
    crontab -r
fi
crontab -l
```

保存 `图08_cron清理结果.png`。原本没有任务且没有新增其他任务时，应显示 `no crontab for testuser`。本节依赖前面同一个 Shell 中的 backup_dir 变量；如果终端已重连，先用 `ls -dt cron_backup.*` 找到本次备份目录，再设定实际路径后继续，不能猜测备份。

## 图13 系统日志的命令行替代

当前普通账户不能读取系统 journal 以及 cron、messages、secure。若前面的 cron 部分通过 `su - testuser` 切换账户，先执行 `exit` 回到原来的 root Shell，并用 `whoami` 确认显示 root。然后运行：

```bash
journalctl -b -n 15 --no-pager
tail -n 10 /var/log/cron
tail -n 10 /var/log/messages
```

分别保存为 `图13a_系统日志.png`、`图13b_cron日志.png`、`图13c_messages日志.png`，画面中隐藏与实验无关的私人信息。如果在普通账户中直接操作，则以上命令加 sudo。参考材料列出的其他日志可能在本系统中不存在，无需人为创建空日志。
