## 1 识别材料与建立清单

定位本次实验目录中的 A、B、全部截图。A 可能为 DOCX 或 PDF；B 通常为 `实验报告模板_副本.docx`。文件名或版本存在歧义时询问，不凭“副本”字样选错文件。已有实验一、实验二成品仅供参考，不取代本次 A、B。

使用本次可用的 documents 技能；A 为 PDF 时同时使用 pdf 技能。通过工作区依赖工具获取当前运行时及库路径，不沿用旧缓存版本或临时目录。

若相应技能、依赖工具或渲染器缺失，先检查当前环境已有的文档/PDF 能力，并继续可完成的读取和编写；说明具体缺少的能力。没有可靠视觉验证时只能交付注明限制的可编辑进度，不能宣称报告已验收完成。

完整读取 A、B，在任务临时目录建立两份工作清单：

- **题目清单**：实验编号、正式题目、实验目的、实验内容、操作过程、操作要求、操作步骤、思考题、讨论题及所有子题，记录原文和来源位置。
- **截图映射**：每张截图的路径、可见命令/程序、输出或报错、所属题目、可支持的结果。按内容匹配，不能按哈希文件名、文件排序或旧截图数量配图。

DOCX 阅读范围包含正文、表格、文本框、页眉页脚等，不仅是 `Document.paragraphs`。PDF 对照完整页面校对提取结果；仅排版断行可以合并，识别不清的字符要核实。先看全部截图，可先生成临时缩略图总览，再逐张读取关键细节。

## 2 原文与作答的边界

| 内容 | 填写方式 |
| --- | --- |
| 正式题目、实验目的、实验内容中的题目与要求 | 按 A 原文复制 |
| 操作过程、操作要求、操作步骤、思考/讨论问题及子题 | 按 A 原文复制，顺序与题号完整 |
| 实验环境、姓名、学号、日期 | 按本次事实与已确认项目约定填写 |
| 实验结果、答案、讨论解答 | 自行撰写，以本次截图和正确原理为依据 |
| 实验体会 | 自行撰写，联系实际操作和发现 |

A 没有单独“操作要求”栏目时，不伪造原文要求。B 栏目不足时按其已有样式扩展，保留 A 的全部内容层级。复制的命令、标点和原有错字也保留；需要纠正时在答案或结果分析中说明正确写法，不能悄悄改题目。

## 3 在 B 上填充并保留格式

先检查并渲染 B，记录实际字体、字号、加粗范围、段落样式、行距、缩进、页边距、分节、装饰线及图片位置。继承 B 的真实格式，不套用通用新文档设计。

从 B 的副本编辑已有位置，新增内容复用对应标题、正文、步骤、思考题、答案的格式原型；不要用第一段或第一个加粗 run 的格式套全文。保留不需要修改的样式、主题、页眉页脚和图形。B 有 VML 装饰线或复杂结构时，优先定点修改 OOXML；技术细节见 [格式保留与预览检查](references/docx-fidelity.md)。

将封面所有相关编号与正式题目更新为本次实验，包括“实验1报告”“实验一 题目”等不同位置，保持字体和排版。清除模板中的待填示例、旧系统环境、旧体会和省略号占位。

通常沿 B 的栏目填写：环境 → 目的 → 内容/操作过程及结果 → 思考/讨论答案 → 体会。不固定题数、截图数、页数或 A/B 段落索引。内容增加可自然增加页数，不压缩字号来强塞原有页数。

将用户截图原样嵌入对应操作或答案附近，按比例缩放到正文可用宽度内；高图兼顾页面高度和文字清晰度。必要时添加沿用 B 正文字体的图号/图注。图片与图注同页，标题与后续内容相连，完整结构图或短代码段尽量不跨页。

报告列出各题实际使用的完整源码，使用可编辑文字、Consolas 字体和完整外框；不以代码截图、省略号或只列关键片段代替。保留缩进，代码框在正文宽度内自然换行。多程序或共用程序明确标出文件名与用途，代码内容逐行核对本地交付文件，详见 [源码展示规范](references/c-code.md#报告中的源码)。

## 4 根据证据独立写结果与答案

逐题交代实际输出及其含义，数值、账户、路径、PID、权限、文件内容与截图一致。参考 A 的题意和结构，不沿用 A 作者的答案、账户、日期或截图。

截图中的失败也属于结果。例如 ln 的 `File exists` 表示本次链接创建失败；sudo chown 的 `not in the sudoers file` 表示 chown 没有执行成功。失败影响须按截图的实际命令判断，其他 sudo 操作不能套用 chown 的结论。先说明真实状态，再分析“若操作成功”的原理；不同文件内容相同不等于已证明硬链接，通常需 inode 或其他证据。

未展示的操作不写成已经实测成功。可提供正确命令、理论解释和明确标识的预期结果；关键题无法据材料判断时及时询问。知识点拿不准时核对权威资料，但报告默认不设“参考资料”栏目，不添加 `[1]` 这类引用编号。题目明确要求列出文献时按题目处理；用户的新要求优先。

结果分析直接写操作、输出和原因，思考题直接回答原理。正文、图注与体会不写“简化版”“新版”“旧版”“简化前运行记录”“需重新截图”等修改过程，也不写“截图本身不提供耗时测量”“不能把可能变化写成已观察到变化”等审稿说明。截图与当前源码有差异时，在对话中说明具体差异和需补的截图；报告如实分析图中现象，不伪造新的运行结果，不把差异改写为已验证一致。

体会围绕具体认识与问题撰写，不照抄 A 或 B 示例，不虚构“第一次接触”、故障修复或未做过的操作。现有截图足以完成写作时，无需重新 SSH 执行实验或修改远程主机。

## 5 核对并交付

完成前逐项检查：

1. 对题目清单逐项比对，目的、步骤、题号、子题无漏抄或擅改。
2. 对截图映射核对位置、图注和结果，报错与正文一致，理论推断与实际结果区分清楚。
3. 检查姓名学号日期、封面各处实验编号、栏目内容，无旧报告残留。
4. 比对 B 的字体、字号、加粗范围、段落属性、页边距和保留结构；新增内容沿用对应格式。
5. 使用 documents 技能的 `render_docx.py` 渲染成品，逐页打开 PNG 检查中文显示、截图清晰度、分页、重叠、裁切和空白。提取文字不足以证明排版正确；修订后重新渲染检查。
6. 涉及源码改动时核对报告、本地与服务器版本；确认 `int main()`、标准输入选择模式、完整源码、Consolas 和边框等本次适用约定。保留必要接口与同步机制，不为了形式删掉实验功能。

渲染中文缺字时按 [预览字体排查](references/docx-fidelity.md#中文预览缺字) 修复预览环境，保留 DOCX 原字体。无法可靠预览时如实说明限制，仅交付尚未完成视觉验证的可编辑进度，不宣称排版已验证或报告已完成。

最终交付完成的 DOCX 和简短说明；预览 PNG、PDF、脚本、截图映射等中间材料放临时目录，不混入实验文件夹，也不作为最终附件。原材料有未解决的实质缺口时说明，并保留可继续编辑的进度。
