# Computer use 截图方法与验收要求

## 三类图片分别使用

| 类型 | 用途 | 存放 |
| --- | --- | --- |
| 操作观察图 | 判断窗口、焦点、控件和当前操作状态 | 任务临时目录，需要时保存 |
| 实验运行截图 | 证明本次命令、输入、输出和报错 | 本次实验目录的 `截图/`，保留原始文件 |
| 报告页面预览 | 检查 DOCX 排版、分页与图片可读性 | 任务临时目录，不充当运行证据 |

用户已有截图原路径保留，不因整理而移动或覆盖。只修改报告且现有证据足够时，不为截图重新连接服务器或重跑实验。

## 用 computer use 截图

1. 先读取当前 `cua_repl` 工具说明。首次调用或重置后，单独执行一个合法入口，例如 `await cua.getState()` 查看应用清单，或已知应用时执行 `let terminal = await cua.getApp("com.apple.Terminal")`。先阅读返回的 API 文档，再继续调用；不猜测方法或参数。实际使用 Otty、Termius 等时绑定清单里的真实应用，不默认切换终端。
2. 用 `cua_repl` 操作真实窗口；浏览器任务按当前文档绑定真实标签页。不要用 AppleScript、osascript 或其他自动化库替代 computer use。文件写入不属于 UI 操作，可以使用运行时支持的文件 API 保存截图字节。
3. 每轮 UI 操作后调用目标的 `getAXState()`，根据最新状态决定下一步。截图前确认目标窗口、会话、工作目录和结果已显示；原生终端中的 SSH 会话须符合 [服务器规范](server.md)。不把聊天中的工具输出当成终端窗口。
4. 通过 `await terminal.getScreenshot()` 或 `await tab.getScreenshot()` 获取目标画面。方法默认已显示图片，不再重复 `emitImage`；需要同时读取状态与截图时使用 `getAXStateAndScreenshot()`。截图观察之后如需依赖元素编号，先用 `getAXState({ disableDiffing: true })` 获取完整新树。
5. 若需保存图片，保留截图调用返回的原始字节。macOS 应用和浏览器通常返回 `Uint8Array`；返回区域数组的平台逐个保存区域的 `bytes`，并记录区域 ID，不把数组当成单张 PNG。不得假设工具显示图片就已保存到磁盘。
6. 工具自动等待适当的界面刷新；不在每张截图前固定 sleep。程序仍运行时，按实际状态继续观察；只有需要捕获阻塞、等待或并发中间状态时才把中途画面作为该状态的证据。

macOS 保存示例（在 `cua_repl` 中执行，应用已按上文绑定；目录和文件名按本次实验替换）：

```javascript
var shot = await terminal.getScreenshot();
var fs = await import('node:fs/promises');
var shotDir = '/Users/bohao/Desktop/OS实验/实验五/截图';
await fs.mkdir(shotDir, { recursive: true });
await fs.writeFile(shotDir + '/操作01_运行结果_01.png', shot, { flag: 'wx' });
```

这是保存已获取的图片字节，不是另一套截图工具。`wx` 防止覆盖原图；文件已存在时换新序号。仅在当前运行时支持上述文件 API、且返回字节确为 PNG 时使用 `.png`；其他格式保留真实格式。如工具不能导出或保存字节，说明具体限制，不编造本地路径或声称已保存。不要为弥补截图能力而绕过工具限制。

## 截图前整理与内容要求

- 以一个题目、运行模式或需要证明的现象为单位取图。先列出所需证据，数量由题意决定，不机械规定每题一张。
- 展示真实执行的命令、必要输入和完整关键输出；编译截图包含编译命令与诊断，运行截图包含程序命令、模式选择和结果。无输出的成功命令应配合实际状态查询佐证，不能凭空补一句“执行成功”。
- 保留有助识别账户、主机、目录的提示符或窗口上下文；PID、时间、计数等按本次实际值记录，不要求重跑得到固定数值。
- 截图前通过应用 UI 调整窗口和显示范围，使文字在报告正文宽度下仍清晰，命令不因窗口过窄而大量折行。不要擅自更改全局主题或系统设置；只在已有授权范围内调整必要显示。
- 避开无关聊天、通知、其他任务内容和敏感信息；不要打开密钥或将密码输入截图。必要的真实实验账户与路径按报告需要保留。
- 长输出按顺序分张，保留适当重叠行以证明连续性；不能只保留最后几行而遗漏输入、关键输出或错误。可滚动查看已有输出；重跑有副作用的命令前先检查授权和当前状态。
- 等待结果稳定后取图。错误、警告和失败结果也是证据，不为美观删去；修复后重新运行的结果另存新图，明确区分两次运行。

## 真实性、保存与逐张验收

禁止用 Pillow、HTML、绘图工具或 AI 生成终端外观，再把日志、预期输出粘进去冒充实测。不能拼接不同时刻的输出伪装成一次运行，也不能涂改数值、账户、报错或时间。报告页渲染与实验取证是两条独立流程。

默认原图直接入报告，只按比例缩放。用户明确要求裁剪或脱敏时，另存派生图并保留原图，记录处理范围；不能去掉判断结果所需的内容。不要通过锐化或生成式修复“补出”看不清的字，应该重新取图或说明无法辨认。

每张保存后打开实际文件目视核验，而不只检查文件存在。核对：

1. 文件能解码，画面是正确应用及本次运行，没有空白、菜单遮挡、截断或未完成刷新。
2. 命令、输入、输出和关键上下文足以支持对应结论；编译与运行所用源码对应本地交付版本。
3. 文字清晰、长行完整、长输出分图连续；无无关私人内容或凭据。
4. 临时截图映射记录题号、模式、输入、文件绝对路径、可见结果、源码版本或摘要，以及重跑/派生图关系。不得根据文件名猜测内容。
5. 嵌入 DOCX 后重新渲染相关页面，在最终页面尺寸检查文字是否可读、图片是否变形/裁切、图注是否对应且同页；必要时拆分图片或调整分页，不靠缩小到无法阅读来塞满一页。

代码修改后旧图仍对应旧运行。已授权且可安全重跑时重新取证，否则在对话中说明差异与缺口，继续完成不依赖新图的内容；不能宣称旧图验证了新代码。用户只要求更新本规范时，不主动执行实验或采集其无关应用画面。
