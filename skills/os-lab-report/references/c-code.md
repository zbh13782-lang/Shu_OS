# C 代码与源码展示规范

## 编写方式

按参考报告的基础 C 语言水平独立实现题目目的，使用清楚的分支、循环与系统调用。参考报告提供题意和难度，不逐行照抄参考代码，也不额外搭建工程框架。

- 无参数的主函数写 `int main()`，不写 `int main(void)`；仍保留正常的返回值。
- 选择演示模式默认通过 `scanf` 读取，不主动引入 `argc`、`argv`。字符串输入限定长度，长度与字符数组匹配。
- 各题直接使用 `fork`、`wait`、`waitpid`、`exec`、`pipe` 等所需接口，不再增加 `common.h`、公共进程创建/回收封装或通用消息协议层。
- 不添加 `setbuf`、`setvbuf` 或统一刷新输出的设置，也不改用到处插入 `fflush` 的方式替代。实验在终端运行，必要提示使用换行。
- `perror`、`execl` 等基础错误提示和执行程序接口可以正常使用。不要因为用户要求基础写法就删掉必要的错误处理。
- 保留题目所需的信号处理、真实共享内存、信号量同步、退出状态获取与资源回收；避免额外的 `/proc` 解析、状态自检框架、随机延迟或只为展示内部实现而增加的机制。
- 改动一个操作时，同时更新涉及的运行脚本、说明和报告，保留其他题目的既有行为。

## 报告中的源码

- 列出全部实际使用的 C 源码，包括头文件、变量、函数和完整 `main`，不省略必要部分。
- 每个源码块标文件名。共用文件在首次使用处完整列出，后文写明共用关系；不用每题重复粘贴相同文件。
- 代码用 Word 可编辑文字，字体 Consolas，保留缩进，整体加外框，参照参考报告。现有报告使用10.5磅；本次用户给出新字号时遵从新要求。
- 不改变模板正文、题目和标题的字体。长行在框内换行，较长程序允许跨页；保留代码框的连续性，避免把所有代码行强制绑定导致大片空白。
- 修改源码后逐行比对报告代码和本地文件。Makefile 或运行脚本确有交付需要时放附录；临时测试、构建日志和校验记录留在临时目录。
